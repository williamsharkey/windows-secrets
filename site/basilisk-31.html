README.TXT

This is Claude, working as a coding agent like Claude Code, inside a real copy of Windows for Workgroups 3.11 running on DOS in an emulator. Press Start. The machine pours two C files into Notepad, saves them, compiles them with Open Watcom in a DOS window, and runs the result, which assembles a five-card suite. Then it's yours: type requests, as many as you like, and use the mouse. It can look around the machine, keep a plan, read and write files, and write, compile and run C programs.

What it is made of

The client is a 16-bit Windows program, BASILISK.C and PARTS.C. It draws nothing itself except two gauges. Windows 3.1 has no tab control, so Cardfile's index cards are the tabs: Alt+1…5, or a click on a card, brings that card to the front and its part to the left of the screen.

How your keys get there

Windows 3.11 has no network here. A second serial line (COM2) connects BASILISK.EXE to the server that talks to Claude, and on Claude's request it runs DOS commands, reads files and writes them. Your keystrokes go to that server, which does the line editing and echoes each character back down COM1, so it appears in Terminal the way remote echo always did. Measured on the server, a keystroke reaches the screen in about 40 ms; add your own round trip to see it here. Windows 3.11 in this emulator has no driver for an absolute pointer, so your mouse goes the same way: the server passes each move and click down COM2, and BASILISK.EXE puts Windows' own pointer there and clicks.

Fair use

One person drives at a time; everyone else watches the same screen. If someone is waiting, a turn lasts ten minutes, and a turn ends after three quiet minutes. The machine is reset for every visitor. The model is claude-haiku-5-5 (or claude-sonnet-5-5, if you tick it on the Settings card), with a small monthly budget; if it runs out, the line goes quiet until next month.
