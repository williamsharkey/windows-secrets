Recorder: the puppeteer that shipped in 1990

The window puppetry films on this site drive other programs' windows from outside. Windows 3.0 shipped a program that did the same thing. Recorder captured every keystroke and mouse event in the system, saved them as a .REC macro, and played them back into whatever program you named. It lasted from 1990 to 1995.

  1. 1990 Windows 3.0 ships Recorder. Its About box says "Developed for Microsoft by Softbridge Ltd." static. Softbridge also sold the Automated Test Facility and the Bridge Toolkit, which Microsoft's knowledge base recommends for editing Recorder macros.
  2. 1992 Microsoft Test, Microsoft's own GUI-testing tool, records and replays the same kind of input.
  3. 1995 Windows 95 leaves Recorder out (KB 159852). The journal hooks it relied on stay in the Windows API.
  4. 2009 Windows 7 brings back a recorder in name only: the Problem Steps Recorder, which takes screenshots of your clicks for a bug report and doesn't play anything back.
  5. 2021 Power Automate Desktop puts a free macro recorder back in Windows 11, 26 years after Recorder left.

How it worked: three hooks

RECORDER.DLL ("Recorder Library") exports JRHOOK, JPHOOK and KHOOK static. They're a journal-record hook, which copies every input event in the system, a journal-playback hook, which feeds events back in as if from the hardware, and a keyboard hook for the shortcut keys. The library also checks where a played-back mouse event will land, using WindowFromPoint, GetClassName and lstrcmp. That's why the error strings read like a puppeteer's worries static:

Strings 1035 and 1036 are the format of a hidden window. Hold Shift while choosing Macro ▸ Properties and Recorder shows Macro Events instead of the Properties dialog. It's a list of every recorded event and the window it went to. The code checks GetKeyState(VK_SHIFT) just before it picks dialog 117 over 109 static. Microsoft did document this, in KB Q62647. Terminal, the other contractor

Recorder wasn't the only accessory Microsoft bought in. Terminal's About text says "Developed for Microsoft by Future Soft Engineering, Inc.", the makers of the DynaComm terminal program. The name hidden in its NE header is Windows Terminal Version 3.00 static. Twenty-nine years later Microsoft used "Windows Terminal" again, for a different program.

Prior art Shift+Properties is in Microsoft's own KB Q62647, and Softbridge's role is mentioned in KB Q72855. The hook exports, the window-matching code path and the MODULE!Class addressing are read from the 3.11 files here. I haven't seen them connected before to how puppetry finds its windows.
