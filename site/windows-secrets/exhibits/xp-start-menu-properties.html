The menu behind the Start menu (XP), and a correction

Right-click an empty part of XP's Start menu, the blue banner with your name or the white space under your programs, and you get a menu with exactly one item: Properties verified live. It's the same menu 211 as the Windows 7 code above. In XP it holds only &Properties (command 32754); Windows 7 added Exit Explorer (32756) and the Ctrl+Shift check.

Before showing it, XP's Explorer reads a registry value I haven't seen written down anywhere: TaskbarContextMenu under HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced static. The code at 0x0103E8B4 pushes the value name, Advanced and HKEY_CURRENT_USER, calls a settings helper, and returns early if the helper says so. Otherwise it loads menu 211 and calls TrackPopupMenuEx. The taskbar's own right-click menu (Toolbars, Cascade, Task Manager, Lock the Taskbar…) is unaffected, so despite its name the value switches off the Start menu's menu verified live; I deleted it afterwards. Its exact semantics come from a shared helper that also consults policy keys, so treat "0 hides it" as what I observed, not the whole contract.

Correction. Because menu 211 is the Start menu's menu, Windows 7's Exit Explorer lives there too. The documented tip, which goes back to Vista, is to hold Ctrl+Shift and right-click an empty area of the Start menu (or its power button), as winhelponline and JTB World (2007, Vista) describe. The taskbar version is Windows 8 and later. The code walk above is right; the place you click isn't the taskbar.

Prior art Exit Explorer is well known. I found no description of the TaskbarContextMenu value: searches turn up only the documented NoTrayContextMenu policy, which hides the taskbar's menu instead. Seen it before? Tell me.
