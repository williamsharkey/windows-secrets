# BASILISK LIVE

A public live-stream theatre: visitors watch a **real Windows XP machine** (QEMU on the
droplet) and one at a time may wake BASILISK and type the two questions its console asks.
The answers come from the Anthropic API (server-side) or, when the line is quiet, from the
films' recordings. **Nothing from Windows reaches a browser except the video/audio stream**:
the guest can only pick from a whitelist of phase names; every other byte a browser sees is
generated by `server.py`.

```
 browser ── https://live.williamsharkey.com ── Caddy :443 ── 127.0.0.1:8780 ─┐
   site/xp-live.html (static, Tigertech)                                     │ server.py
                                                  /hls/*  /poster.jpg  /ws   │ (aiohttp, venv)
                                                                             │
   streamer.py ── HMP /tmp/stage-mon.sock (screendump, 15 fps) ─┐            │ QMP /tmp/stage-qmp.sock
              └── parec  <- PulseAudio null sink "stage" <──────┤            │ (loadvm, savevm)
              └── ffmpeg x264+AAC -> /dev/shm/stage-hls (fMP4)   │            │
                                                        stage VM (QEMU, XP SP3, 512 MB)
                                                        guest 10.0.2.2:8765 ──guestfwd──> 127.0.0.1:8770
                                                          agent.exe  (/next, /out)       server.py guest side
                                                          puppet.exe (/mark /question /claude)
```

Everything lives in `/root/stage` on root@165.227.188.129. It shares the box with the
production catenary services (Caddy on 80/443) and two other XP VMs (`studio-xp`, `xp2`);
nothing here touches their sockets, ports (8765/8767/8779/8788...) or disks.

`bin/stagectl run "dir C:\p" | reset | abort | status | hmp "info snapshots"` drives the

streamer runs (single-client socket); use `stagectl hmp` (QMP) instead.

## The stage VM

* Disk: crash-consistent copy of `/root/xp/winxp.qcow2` taken from the running studio VM
  with `drive_backup -f ide0-hd0 /root/stage/stage.qcow2 qcow2` (one HMP command, while
  qrec wasn't connected).
* `-netdev user,restrict=on,host=10.0.2.100,guestfwd=tcp:10.0.2.2:8765-cmd:socat STDIO TCP:127.0.0.1:8770`:
  the guest reaches nothing but our server. (A `tcp:` guestfwd target is a single chardev
  connection for the VM's whole life; `cmd:` spawns socat per connection, which HTTP needs.)
* Sound: `-audiodev pa` into a private PulseAudio (`stage-vm.sh pulse`, socket
  `/root/stage/pulse/native`, null sink `stage`); `parec stage.monitor` gives a gap-free
  stream (silence when XP is quiet). QEMU's wavcapture/`-audiodev wav` only produce data
  while the guest plays, and a FIFO target would block QEMU when no reader is attached.
* Stage: `basilisk-setup.bat` (launch-week desktop, Oct 25 2001 10:21), `puppet test icons`
  (basilisk.exe in the middle, `C:\p\iconpos.txt`), Notepad font back to default, the timeout-safe
  agent in Startup; then `savevm stage-ready` (168 MiB).
* Reset: `loadvm stage-ready` **0.3-0.45 s** (measured). After a loadvm the in-guest agent
  needs up to ~8 s to notice its stranded connection (socket timeout), so a show starts
  ~9 s after the button.

To re-stage: `stagectl reset`, change things with `stagectl run ...`, then
`stagectl hmp "savevm stage-ready"`.

## The show

`Wake BASILISK` -> (per-IP wake allowance) -> queue -> `loadvm` -> agent `spawn puppet.exe intro`
(the curious user right-clicks the stranger, opens Properties, double-clicks it by accident ->
`basilisk.exe` = the V1 BASILISK scene). The puppet reports acts with `GET /mark?p=` (intro,
wake, paint, swallow, devour, console, end) and asks `GET /question?k=0|1` (long-poll,
`STAGE_QWAIT`=45 s; the swarm of calculator keys spells SPEAK TO ME... meanwhile). The visitor
who woke it can type question 0 from the start of the show, question 1 after the first answer.
No question in time (or they left, or hit a limit) -> the film's scripted question. Then
`POST /claude` -> answer (API, or recording). After `end` the last frame holds ~17 s, then
`loadvm` and idle (or the next visitor's show). Hard stop: `STAGE_SHOW_MAX` (600 s).

Puppet changes keep the films working: the studio server answers `/mark` and `/question` with
404, which the puppet treats as "use the script".

## Answers, budget, limits

* Model `claude-haiku-5-5` (set `STAGE_MODEL=claude-sonnet-5-5` in `.env`), effort `low`,
  `max_tokens` 1024; the fixed frame (relay.py's FRAME + live-performance guidance, >512
  tokens) is the cached system prompt; the visitor's words follow it. Replies pass through
  `ascii_only`, markdown stripping and a 300-char cut; the puppet filters again.
* No key, or spend >= 90% of the cap, or the global API rate is exceeded -> the line is
  quiet: the scripted questions get the film's answers, typed questions get one of three
  recorded lines starting "The line is quiet..."; the page shows a quiet note.
* `.env` is re-read before every API call and on `SIGHUP` (`systemctl reload stage-server`),
  so installing the key needs no restart.
* Spend = usage tokens x price (input, cache write 1.25x, cache read 0.1x, output; Haiku 5.5
  $0.10/$0.50 per MTok), per calendar month (UTC) in `data/spend.json`.
  `STAGE_MONTHLY_CAP_USD` default 25. A typical answer costs well under $0.001.
* Visitor text: control chars stripped, NFKD -> ASCII, whitespace collapsed, 120 chars,
  a small slur/sexual/violence/credential pattern list and links are refused before XP or
  the API sees them; the system prompt tells the model to decline the rest briefly.
* Per IP (from `X-Forwarded-For` only when the TCP peer is `127.0.0.1` = Caddy): one wake per
  20 min (`STAGE_WAKE_EVERY`), questions 6/hour (`STAGE_Q_HOUR`), 20/day (`STAGE_Q_DAY`);
  global 90 API calls/hour (`STAGE_API_HOUR`); queue max 20, one place per IP; at most 8
  sockets per IP; WebSocket messages over 20/10 s are ignored.
  Soft first: past half an allowance a question is delayed 2-10 s with "The line is busy;
  your words are on the wire..." and recent wakers queue behind first-timers. Hard: one calm
  line "BASILISK is resting for you until 4:30 PM" (browser local time). Watching is never
  blocked.

## Measured (2026-11-07, 8 vCPU droplet)

* Stream: 1024x768 @ 15 fps, H.264 main (veryfast, zerolatency, CRF 26, 2 s GOP = 2 s fMP4
  segments) + AAC 64 kb/s. Still desktop ~0.5-0.8 Mb/s (Bliss keyframes are ~130-190 KB);
  cap 1.5 Mb/s.
* CPU while a show runs: stage QEMU ~135% (two busy vCPUs), ffmpeg ~35%, streamer.py ~7%,
  PulseAudio ~8%, parec ~3%. Idle desktop: QEMU ~25%, ffmpeg ~35-45%.
* Latency: segment cadence 2 s; glass-to-glass ~5-7 s with the page's MSE player (it holds
  ~1.2-3.5 s of buffer), more with Safari's native HLS.
* Reset (`loadvm`) 0.3-0.45 s; show start ~9 s after Wake; show length ~6-7 min.

## Going live

Already done by the parent: DNS `live.williamsharkey.com -> 165.227.188.129`, the Caddy block
(see `Caddyfile.live.snippet`), TLS.

```
# on the droplet: stop the hand-started processes, then run under systemd (not enabled at boot)
cp /root/stage/bin/../systemd/*.service /root/stage/bin/../systemd/stage.target /etc/systemd/system/   # (already copied)
systemctl daemon-reload
systemctl start stage.target            # pulse, VM, streamer, server
systemctl enable stage.target           # ONLY when approved: start at boot
# key:  printf 'ANTHROPIC_API_KEY=sk-ant-...\n' > /root/stage/.env; chmod 600 /root/stage/.env
#       systemctl reload stage-server   (or just wait: .env is read before each call)
```
Upload `site/xp-live.html` to williamsharkey.com (`~/html/live/`), and add it to the sibling
navs when ready. The page's server defaults to `https://live.williamsharkey.com`;
`?server=http://localhost:8780` points it elsewhere (local test: `ssh -L 8780:127.0.0.1:8780 root@165.227.188.129`).

## Decisions for the user

1. **Public hostname** - chosen: `live.williamsharkey.com` (Caddy block on the production
   Caddyfile, applied). Alternatives were a catenarystudio.com subdomain or a separate host.
2. **API key and monthly cap** - put the key in `/root/stage/.env`; cap is $25/month
   (`STAGE_MONTHLY_CAP_USD`), recorded answers from 90% of it.
